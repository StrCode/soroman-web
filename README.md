# Soroman Web

The customer-facing web app for **Soroman Energy** — order fuel and energy
products, track deliveries, and manage your account.

It is a single-page React application that talks to the Soroman backend over a
JSON API. Customers use it to place and track orders across Soroman's channels
(Dangote diesel/PMS delivery, depot pickup, and — behind a flag — cooking-gas
cylinder delivery), manage licenses and a wallet, and handle their profile and
settings. Public marketing, help, and legal pages live in the same app.

> **Not TanStack Start / SSR.** Despite the scaffold's origins, this is a
> **client-rendered SPA** (`routerOnly`). There are no server functions, API
> routes, or server rendering here — all data comes from the backend at
> `VITE_SERVER_URL`.

## Getting started

Requires [Bun](https://bun.sh) and a running instance of the Soroman backend
(or a URL to a deployed one).

```bash
# 1. Install dependencies
bun install

# 2. Configure the environment
cp .env.example .env
#    then edit .env and point VITE_SERVER_URL at your backend

# 3. Run the dev server (http://localhost:3000)
bun run dev
```

## Environment

Client env vars are validated at startup by `src/env.ts` — a missing or
malformed value fails the build/boot with a clear message. All client vars are
prefixed `VITE_` and exposed to the browser.

| Variable | Required | Default | Purpose |
| --- | --- | --- | --- |
| `VITE_SERVER_URL` | ✅ | — | Base URL of the Soroman backend API. |
| `VITE_COOKING_GAS_ENABLED` | — | `false` | Feature flag for the cooking-gas (LPG cylinder) channel. When off, its wizard, dashboard, and API calls are hidden. |
| `SKIP_ENV_VALIDATION` | — | — | Set to any value to bypass env validation (escape hatch for tooling). |

## Scripts

```bash
bun run dev              # Vite dev server on port 3000
bun run build            # Production build to dist/
bun run preview          # Preview the production build locally
bun run start            # Serve dist/ as an SPA (honours $PORT, defaults to 3000)
bun run generate-routes  # Regenerate src/routeTree.gen.ts from src/routes
bun run check-types      # vite build + tsc --noEmit
bun run lint             # Biome lint
bun run format           # Biome format
bun run check            # Biome lint + format check
```

The route tree (`src/routeTree.gen.ts`) is generated by the TanStack Router
Vite plugin — it regenerates automatically during `dev` and `build`, so you
rarely need `generate-routes` by hand.

## Project structure

```
src/
  main.tsx            App bootstrap: QueryClient, Router, session restore
  env.ts              Typed, validated client env (@t3-oss/env-core)
  index.css           Tailwind entry + design tokens
  routeTree.gen.ts    GENERATED — do not edit by hand
  routes/             File-based routes, grouped by layout (see below)
  components/         UI, grouped by domain (auth, dashboard, order, ...)
  lib/                API client, transport, auth store, domain helpers
  hooks/              Shared React hooks
```

### Routing layout groups

Routes are organised into three pathless layout groups, each with its own
chrome:

- **`_site`** — public marketing, help, and legal: home, FAQ, terms, privacy,
  contact, account-deletion, and order tracking (`/t/$ref`).
- **`_slim`** — minimal-chrome task flows: `login`, `register`,
  `forgot-password`, and the order wizards (`order`, `order/new`,
  `order/depot`, `order/dangote-delivery`, `order/cooking-gas`).
- **`_authed`** — the signed-in dashboard (guarded in `beforeLoad`): orders and
  order detail, prices, wallet, licenses, commissions, notifications, profile,
  and settings.

### Data & state

- **`src/lib/http.ts`** — the transport layer: base URL, cookies, bearer token,
  CSRF echo, and the serialized refresh-on-401 flow. Knows nothing about domain
  shapes.
- **`src/lib/api.ts`** — the customer API client built on top of it. Some
  namespaces the backend doesn't serve yet are still mocked and say so at their
  definition.
- **`src/lib/auth.ts`** — a small external store (`useSyncExternalStore`)
  holding `loading | guest | authed`, restored once on startup.
- **TanStack Query** owns caching; route loaders and preloading run through it
  and dedupe.

### Authentication model

Phone-first, passwordless by default:

- **New device:** sign in with your **phone + a one-time SMS code (OTP)**. New
  numbers register on the way in.
- **Trusted device:** once a device has proven the phone by OTP, you can sign in
  with a **6-digit PIN** against either identifier on the account (email _or_
  phone).
- **Transport:** the refresh token is an httpOnly cookie (never readable in JS),
  the 15-minute access token lives in memory only, and a CSRF double-submit
  token is kept in `localStorage`. A 401 triggers a single serialized refresh
  before failing.

The backend deliberately never reveals whether a phone number is registered
(anti-enumeration), so the sign-in UI treats known and unknown numbers
identically and offers a hand-off into registration when a code doesn't arrive.

## Building & deploying

```bash
bun run build      # → dist/ (static assets)
bun run start      # serve dist/ with SPA fallback on $PORT
```

The output in `dist/` is a static SPA. Host it on any static host or run the
bundled `serve` (`bun run start`) — both must serve `index.html` as the
fallback for unknown paths so client-side routing works. Set `VITE_SERVER_URL`
at **build time** for the target environment.

## Code style

Formatting and linting are handled by Biome (`biome.json`). Run `bun run check`
before pushing; TypeScript is `strict` with `noUnusedLocals` /
`noUnusedParameters`, so unused code fails the type check.
